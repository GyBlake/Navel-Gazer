# Security Policy

Do not place secrets, personal data, credentials, private keys, or sensitive records in issues or pull requests.

Security reports should use GitHub's private security reporting mechanism when available. Include affected version/commit, component, reproduction steps, impact, and mitigation if known.

Security principles: least privilege, explicit authorization, input validation at trust boundaries, provenance preservation, explicit unknown/blocked states, dependency review, secret protection, and validated releases.


## Baseline relationship

`SECURITY_BASELINE.md` defines the required security-control baseline. This policy defines operational handling and disclosure. The baseline is normative for repository controls; this policy is normative for security-report handling.

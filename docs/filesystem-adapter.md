# Filesystem adapter

The filesystem adapter is the first external resource adapter in the public reference implementation.

It provides a deliberately narrow, read-only path:

`filesystem path → resource registration → capability check → authorization → runtime execution → result + evidence + provenance + event`

## Security boundary

The adapter requires a configured root directory and accepts only paths relative to that root.

It rejects:

- absolute paths
- parent traversal outside the configured root
- symlink targets that resolve outside the configured root
- non-file resources
- files larger than the configured `maxBytes` limit

The default maximum read size is 1 MiB.

## Authorization

Authorization remains deny-by-default. A caller must supply a policy allowing the subject to read the exact registered resource, or use an explicit wildcard rule.

The adapter does not grant authority merely because a file exists.

## Evidence and integrity

Execution events retain structured evidence and provenance generated by the runtime. The adapter also returns a SHA-256 digest and byte count so callers can independently identify the returned content without placing the full content into the event record.

This adapter is intentionally read-only. Write, delete, watch, and arbitrary command execution are outside its contract.
